# 0006：命令历史与单槽本地保存

后续用户反馈要求多个实验分别保存，单槽约定已被覆盖：当前使用数据库版本 2、按 documentId 存储的实验列表，原单槽剩余快照备份迁移；见[更新契约](../models/history-and-persistence.md)和[多实验验收](../acceptance/M1-MULTI-SAVE.md)。以下保留任务 04 初版决策背景。

日期：2026-11-03。范围：原方案第 15 章任务 04（M1），沿用用户实物器材、单节电池电压和自由导线修订；未开始任务 05 电路求解。

采用独立的类型化 SceneCommand 与验证后的文档快照历史，复用任务 03 的单次松手提交，不引入状态管理或持久化库。快照保留器材 ID 与相连导线完整状态，减少手写删除逆操作丢失自由端/曲线的风险。无效/无变化操作不入栈；有效新编辑清空 redo；视口保存但不进入历史。撤销/重做递增 revision，保留当前视口。

历史各栈按 100 项 / JSON UTF-16 估算 20 MiB 限制，不保存整个编辑历史到文件；切换文档及刷新后从新历史开始。测量记录仍完整保存，但采样、记录表编辑与动态仿真不在本任务内。

使用原生 IndexedDB 的 readwrite 事务保存单个 latest JSON 快照。手动“保存”，启动自动恢复最近保存，“加载”提供预览确认；未保存更改不会自动写入本地。先保持一个清晰可验收的最近保存槽，不增加模板库、云端或多标签同步。存储失败后允许用户导出 JSON。

当前格式保持版本 2；v1→v2 用旧 schema 严格校验后仅提升顶层版本，再用当前注册表及引用规则校验。已知历史 junction 不丢弃，未知器材/版本不跳过。5 MiB UTF-8、200 器材、500 连接、10000 记录限制适用于导入和结构校验，导出也受相同文件字节限额。JSON 解析时显式拒绝原型相关键，禁止校验库忽略字段；文件只当作数据。

导入和手动加载显示原生 dialog 预览，确认前不更换场景，确认清空当前历史；失败/取消保留当前工作。页面、预览、恢复提示明确重载从初态重新运行，文件不承诺动态续跑。

详细契约见[命令与持久化说明](../models/history-and-persistence.md)，实际证据见[验收](../acceptance/M1-TASK04.md)。不新增依赖、不修改原方案与现有代码注释；原创代码授权仍以现有待确认记录为准。
