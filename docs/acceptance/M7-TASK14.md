计时方法：原生 requestAnimationFrame 统计显示节拍；DOM input 事件到后续两帧统计界面响应，Worker postMessage 到实际回包单独统计。静态场景的 rAF 节拍不意味着每帧重新求解；该测量也不等同于物理显示器呈现或每次求解结果完成的端到端延迟。记录的界面响应满足本机 ≥30 FPS、P95<100 ms 目标。

负载场景为可求解的 50 器材 / 100 连接 / 50 节点，含两只非线性灯泡；100 条连接包括平行重复导线用于绘制/节点合并负载，不冒充 100 个独立未知量。归一化 KCL/本构/功率残差均低于 1e-6，没有降低物理解算精度。光学仍是现有单透镜/三条辅助光线模型，未伪称交付了 300 射线、多次反射的通用追迹器。

60 次替换后，同一光学场景 documents=1、DOM 节点 4815→4816、监听数 226→226；待执行应用 rAF=0、活动 Worker=0。10 个真实 Worker 回复延迟到场景替换后投递，未污染当前光学状态；最终连续运行结束后也无残留 rAF/Worker。强制 GC 的 JS 已用堆约 6.96→10.18→11.62 MB（首次冷态、60 次切换后、长测后），增长未隐瞒；测量脚本自身保存帧/响应数组，且存在引擎预热，因此本轮不能证明无限时长绝无堆泄漏。DOM/监听和应用 rAF/Worker 未见随切换累加，多小时实体机稳定性仍可继续观察。
